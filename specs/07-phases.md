# 07. 개발 Phase 계획 (Phase 1 ~ 7)

> 각 Phase는 **작동하는 상태로 끝나야** 한다. Phase를 마치면 (1) 완료 기준 확인 → (2) README의 진행 현황 갱신 → (3) 변경된 스펙 반영 순서로 마무리한다.
> 이 문서의 체크박스는 Phase 진행 중 Claude가 갱신한다. `[A-xx]`는 `99-assumptions.md` 참조.
> **현재 상태: Phase 6 완료, Phase 7 시작 전**

| Phase | 주제 | 결과물 |
|---|---|---|
| 1 | 프로젝트 기반 · 인증 | 백엔드/프런트 골격, PostgreSQL 연결, 기본 관리자, 로그인 |
| 2 | 관리자 마스터 관리 | 사용자·부서·입력 항목 CRUD |
| 3 | 월 실적 입력 | 입력 폼, 임시 저장/제출, 진행률, 중복 제출 방지 |
| 4 | 엑셀/CSV 업로드 | 업로드 반영, 검증 |
| 5 | 입력 현황 · 연간 목표 | 미제출 모니터링, 상세 조회, 목표 설정 |
| 6 | 지표 계산 · 대시보드/리포트 | 8개 분석 항목, 차트, 월별 리포트 |
| 7 | 다운로드 · 마무리 | CSV 다운로드, 전체 점검, 문서 정리 |

---

## Phase 1. 프로젝트 기반 · 인증

**목표**: 백엔드와 프런트가 연결되어 로그인까지 되는 골격을 만든다.

- [x] `backend/`: Django 프로젝트(`config`), 앱 5개 생성(`accounts`, `organization`, `reports`, `goals`, `analytics`) [A-41]
- [x] 설정: PostgreSQL 연결(환경변수) [A-40], DRF, `LANGUAGE_CODE`/`TIME_ZONE` [A-44], `AUTH_USER_MODEL`
- [x] `organization.Department` 모델 + 마이그레이션 (`User.department` FK가 참조하므로 Phase 1에서 만든다. 초기 데이터·API는 Phase 2) [02 §2.2]
- [x] `accounts.User`(AbstractUser 상속, `name`, `role`, `department`) 모델 + 마이그레이션 [A-09]
- [x] 기본 관리자 자동 생성 (앱 시작 시, 멱등) [A-13]
- [x] 로그인/로그아웃/me API (TokenAuthentication) [03 §2, A-12]
- [x] `frontend/`: Vue 3 + Vite + Vue Router + Bootstrap 5.0(CSS) + Chart.js 설치, Vite `/api` 프록시 [A-38, A-39]
- [x] 로그인 화면, 공통 레이아웃, 라우트 가드, API fetch 래퍼
- [x] `.gitignore`, `requirements.txt`, `package.json` 작성
- [x] CLAUDE.md의 실행/테스트 명령이 실제로 동작하는지 확인 후 갱신

**완료 기준**
- `python manage.py migrate` 후 서버를 켜면 ADMIN/ADMIN/admin1234! 로 로그인된다
- 재시작해도 관리자가 중복 생성되지 않는다
- 잘못된 성명/사번/비밀번호 조합은 동일한 오류 메시지로 거부된다
- 로그인 후 역할에 맞는 홈으로 이동하고 로그아웃이 된다
- 테스트: 기본 관리자 생성(멱등), 로그인 성공/실패

## Phase 2. 관리자 마스터 관리 (사용자 · 부서 · 입력 항목)

**목표**: 관리자가 조직과 입력 항목을 화면에서 관리할 수 있다.

- [x] `InputItem` 모델·마이그레이션(`Department`는 Phase 1), 초기 데이터 마이그레이션 [A-01, A-02]
- [x] 지표 연동 키 고정 목록(코드 상수) + `/metric-keys/` [A-07]
- [x] 사용자 CRUD API + 삭제 제한 [A-15], 비밀번호 재설정 [A-14]
- [x] 부서 CRUD(논리 삭제) + 소속 사용자 있는 부서 삭제 방지 [A-06]
- [x] 입력 항목 CRUD(논리 삭제) (값이 있는 항목의 범위 변경 방지는 `ReportValue`가 생기는 Phase 3에서 구현)
- [x] 화면: `/admin/users`, `/admin/departments`
- [x] 권한: 관리자 전용 API (직원 403)

**완료 기준**
- 관리자가 사용자 추가/수정/삭제, 부서 배정, 부서·항목 CRUD를 화면에서 할 수 있다
- 자기 자신·마지막 관리자는 삭제되지 않는다
- 직원 토큰으로 관리 API 호출 시 403
- 테스트: 권한, 삭제 제한, 논리 삭제 후 이름 재사용, 초기 데이터

## Phase 3. 월 실적 입력

**목표**: 직원이 월 실적을 입력·저장·제출한다.

- [x] `MonthlyReport`, `ReportValue` 모델·유니크 제약 [02 §2.4~2.5]
- [x] `/my-report/{year}/{month}/` GET/PUT/submit API [03 §5]
- [x] 검증: 미래 월, 다른 부서 항목, 중복 (항목, 프로젝트명), 범위별 project_name 규칙
- [x] 제출 검증(필수 항목), 중복 제출 409, 제출 후 잠금 [A-18, A-20]
- [x] 진행률 계산(서버) [A-20]
- [x] 값이 있는 입력 항목의 범위(scope) 변경 방지 (`PATCH /items/{id}/` 400) [A-04] — Phase 2에서 이월
- [x] 소속 부서가 없는 직원의 `/my-report/` 요청 처리 (403 `forbidden`, 99에 A-46으로 기록)
- [x] 화면: `/entry` (월 선택, 안내 문구, 월 합계형/프로젝트별형 입력, 진행률 막대, 임시 저장, 제출, 제출 후 잠금) [04 §3.2]

**완료 기준**
- 임시 저장 → 새로고침 → 값 유지, 수정 후 제출 가능
- 필수 항목이 비면 제출이 거부되고 미입력 항목이 표시된다
- 같은 부서·월 재제출은 409, 제출 후 수정은 409
- 같은 부서 다른 직원이 같은 보고서를 이어서 편집할 수 있다 [A-11]
- 테스트: 진행률, 제출/중복 제출/잠금, 전체 교체 저장

## Phase 4. 엑셀/CSV 업로드

**목표**: 파일 업로드로 월 실적을 채운다.

- [x] 업로드 API (openpyxl / csv) [06]
- [x] 파일 형식·크기·행 수 검증, 행별 오류 목록, 전체 성공/전체 실패 [A-23, A-24]
- [x] 반영 규칙(upsert, 미포함 값 유지, DRAFT 저장) [06 §5]
- [x] 화면: 업로드 영역, 결과/오류 표시 [04 §3.2]

**완료 기준**
- 예시 파일(xlsx, csv)이 폼에 반영되고 진행률이 갱신된다
- 오류가 1건이라도 있으면 아무것도 반영되지 않고 행별 오류가 표시된다
- 제출된 보고서에 업로드하면 409
- 테스트: 정상/오류 케이스별 업로드, 덮어쓰기·유지

## Phase 5. 입력 현황 · 연간 목표

**목표**: 관리자가 제출 현황을 모니터링하고 목표를 설정한다.

- [x] `/status/`, `/status/matrix/`, 부서 보고서 상세 조회 API [03 §6]
- [x] (임시) 제출 되돌리기(reopen) [A-19]
- [x] `AnnualGoal` 모델, `/goals/` GET/PUT [03 §7]
- [x] 화면: `/admin/status`(요약·미제출 모니터링·현황표·상세), `/admin/goals`

**완료 기준**
- 월별 부서별 상태·진행률·미제출 부서가 정확히 표시된다
- 상세에서 입력값을 읽기 전용으로 볼 수 있고, 제출 완료 건은 되돌릴 수 있다
- 목표를 저장/수정/삭제할 수 있다
- 테스트: 상태 집계, reopen 규칙, 목표 upsert/삭제

## Phase 6. 지표 계산 · 대시보드 / 월별 리포트

**목표**: 입력 데이터로 지표를 자동 계산해 대시보드와 리포트에 표시한다.

- [x] 착수 전: 03 §8·05의 응답 스키마 보강과 사용자 승인 [A-50]
- [x] `analytics` 계산 모듈 (순수 함수 중심): 집계(flow/stock/rate) → 8개 섹션 [05]
- [x] `/dashboard/`, `/monthly-report/` API [03 §8]
- [x] 미제출 경고 정보(`data_status`)
- [x] 화면: `/admin/dashboard`(KPI 카드 + Chart.js 차트), `/admin/report`(당월/누적 표) [04 §3.3~3.4]
- [x] 계산 불가 값 `-` 처리 [A-36]

**완료 기준**
- 05 §5 검증 예제의 기대값이 테스트로 통과한다
- 종합·프로젝트별 원가/이익률, 매입·매출·미수금, 자금 수지 예측(3~6개월), BEP, 가동률, 수주·파이프라인, 인당 생산성, 목표 달성률이 모두 표시된다
- 임시 저장(DRAFT) 데이터는 집계에 포함되지 않는다
- 0으로 나누기 등에서 오류 없이 `-` 표시
- 테스트: 지표별 계산, stock 이월(`as_of_month`), 자금 예측, 경계값

## Phase 7. 다운로드 · 마무리

**목표**: CSV 다운로드를 제공하고 PoC를 마무리한다.

- [ ] `/dashboard/export/`, `/monthly-report/export/` (UTF-8 BOM CSV) [A-43, 05 §4]
- [ ] 화면의 `CSV 다운로드` 버튼(fetch → Blob)
- [ ] 전체 흐름 수동 점검: 직원 입력/업로드/제출 → 관리자 현황 → 대시보드/리포트 → 다운로드
- [ ] 취합 시간 단축 목표(부서당 8시간 → 1시간 미만) 관점의 사용성 점검 메모
- [ ] 문서 정리: README, CLAUDE.md, specs 최신화, 99-assumptions 중 확정 항목 반영
- [ ] 알려진 제한 사항 기록 (배포 미포함, 그룹웨어 연동 미포함)

**완료 기준**
- 다운로드한 CSV가 엑셀에서 한글 깨짐 없이 열리고 화면 수치와 일치한다
- 전 Phase의 완료 기준이 유지된다 (`python manage.py test` 전체 통과, `npm run build` 성공)
- README의 실행 방법대로 새 환경에서 기동된다
