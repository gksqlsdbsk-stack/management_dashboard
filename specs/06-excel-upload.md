# 06. 엑셀/CSV 업로드 명세

> 그룹웨어 연동 대신 엑셀/CSV 업로드로 월 실적을 반영한다 (PoC). `[A-xx]`는 `99-assumptions.md` 참조.
> 엑셀 처리는 **openpyxl**, CSV는 Python 표준 `csv` 모듈.

## 1. 개요

- 사용자: 직원. 화면 `/entry`의 업로드 영역 [04 §3.2]
- API: `POST /api/my-report/{year}/{month}/upload/` (`multipart/form-data`, 필드명 `file`) [03 §5]
- 대상: **로그인한 직원의 소속 부서**, **화면에서 선택한 연·월**의 보고서 [A-24]
- 결과: 보고서 값(`ReportValue`)에 반영되어 `DRAFT` 상태로 저장. 제출은 별도 [A-24]
- 이미 `SUBMITTED`이면 409 `report_locked` [A-18]

## 2. 파일 형식 [A-23]

| 항목 | 규칙 |
|---|---|
| 확장자 | `.xlsx`, `.csv` (`.xls` 등 그 외는 400) |
| 크기 | 최대 5MB (5 × 1024 × 1024 바이트) |
| 데이터 행 수 | 최대 1,000행 (헤더 제외) |
| CSV 인코딩 | UTF-8 (BOM 허용). 구분자는 쉼표 |
| xlsx 시트 | 첫 번째 시트만 사용 |

## 3. 열 구조 [A-24]

첫 행은 헤더, 아래 세 열(순서 무관, 헤더 텍스트로 인식, 앞뒤 공백 무시):

| 헤더 | 필수 | 설명 |
|---|---|---|
| `항목명` | ✔ | 소속 부서의 **활성 입력 항목명**과 정확히 일치 |
| `프로젝트명` | 조건부 | 프로젝트별형 항목은 필수, 월 합계형 항목은 비워 둠 |
| `값` | ✔ | 숫자. 천 단위 콤마(`1,500,000`)는 허용, 통화 기호·단위 문자는 불가 |

### 예시 (생산 부서)

| 항목명 | 프로젝트명 | 값 |
|---|---|---|
| 프로젝트별 재료비 | A프로젝트 | 1500000 |
| 프로젝트별 재료비 | B프로젝트 | 820000 |
| 프로젝트별 노무비 | A프로젝트 | 600000 |
| 생산량 | | 320 |
| 생산 능력(월 최대 생산량) | | 400 |

## 4. 검증 규칙

행 번호는 엑셀/CSV의 실제 행 번호(헤더=1행).

| 검증 | 오류 메시지 예 |
|---|---|
| 필수 헤더 누락 | `헤더에 '항목명' 열이 없습니다.` |
| 항목명이 부서의 활성 항목이 아님 | `3행: '기타비용' 항목을 찾을 수 없습니다.` |
| 월 합계형 항목에 프로젝트명이 있음 | `4행: '생산량'은 프로젝트명을 입력하지 않는 항목입니다.` |
| 프로젝트별형 항목에 프로젝트명이 없음 | `5행: '프로젝트별 재료비'는 프로젝트명이 필요합니다.` |
| 값이 비었거나 숫자가 아님 | `6행: 값이 숫자가 아닙니다.` |
| 파일 안에서 (항목명, 프로젝트명) 중복 | `7행: 2행과 중복된 항목입니다.` |
| 소수 4자리 초과·허용 범위(자릿수 20) 초과 | `8행: 값이 허용 범위를 벗어났습니다.` |
| 프로젝트명 길이 100자 초과 | `9행: 프로젝트명이 너무 깁니다.` |

- 항목명·프로젝트명은 앞뒤 공백을 제거한 뒤 사용한다 [A-04, A-48]. 항목명이 비어 있으면 `N행: 항목명이 비어 있습니다.`
- 세 열(`항목명`, `프로젝트명`, `값`)이 모두 비어 있는 행은 무시한다. 헤더에 없는 추가 열은 무시한다 [A-48].
- 한 행에 오류가 여러 개면 모두 보고한다. 검증 순서는 권한 → 연·월 → 제출 잠금(409) → 파일 검증 → 반영이다 [A-48].
- 응답: 오류가 있으면 400 `upload_invalid`, `errors.rows = [{ "row": 3, "message": "3행: …" }, …]` (**한 건도 반영하지 않음** — 전체 성공/전체 실패 [A-24]). `message`는 위 표의 예시처럼 `N행:` 접두어를 포함하고, 헤더 오류는 `row: 1`에 접두어 없이 표시한다.
- **파일 자체 오류**(파일 없음, 허용되지 않는 확장자, 5MB 초과, 데이터 1,000행 초과, UTF-8이 아닌 CSV, 손상된 엑셀 파일, 데이터 행이 하나도 없는 파일)도 400 `upload_invalid`이며 `detail`에 사유를 담고 `errors.rows`는 빈 배열이다 [A-48].

## 5. 반영 규칙 [A-24]

1. 모든 행 검증 통과 → 하나의 트랜잭션으로 반영
2. 보고서 레코드가 없으면 `DRAFT`로 생성
3. 파일의 (항목, 프로젝트명) 조합은 **upsert(덮어쓰기)**
4. 파일에 없는 기존 값은 **유지**(삭제하지 않음)
5. `applied_count` = 반영(생성+갱신)된 값 개수
6. 응답 본문은 최신 보고서 상태(`03 §5`의 GET 형태)를 포함해 화면이 폼을 즉시 갱신할 수 있게 한다

## 6. 화면 안내 문구 (초안)

> 엑셀(.xlsx) 또는 CSV(.csv) 파일을 올리면 현재 선택한 월의 입력값에 반영됩니다. 첫 행에 `항목명`, `프로젝트명`, `값` 열이 있어야 하며, 월 합계 항목은 프로젝트명을 비워 두세요. 파일에 없는 항목은 기존 값이 유지됩니다.

## 7. 추후 확장 (기록만, 구현 안 함)

- **그룹웨어 연동**: 업로드로 채우는 값을 그룹웨어에서 가져오는 방식으로 대체/보완하는 것을 추후 검토. PoC 범위 아님.
- 빈 양식(템플릿) 다운로드는 만들지 않는다 [A-24].
