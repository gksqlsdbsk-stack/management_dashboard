# 99. 임시 가정 목록 (Assumptions)

> **이 문서는 사용자가 직접 수정할 문서입니다.**
> 요구 사항에서 정해지지 않아 문서 작성자(Claude)가 **임시로 정한 값**을 모두 여기에 모았습니다.
> 다른 specs 문서에서는 `[A-xx]` 태그로 이 문서의 항목을 참조합니다.
> 값을 바꾸면 **이 문서만 먼저 수정**하고, 참조하는 문서(“영향 문서”)를 함께 맞춥니다. (Claude에게 “99 수정 반영해 줘”라고 요청하면 됩니다.)

- 최종 수정: 2026-09-21 (초안, Phase 3에서 A-46·A-47, Phase 4에서 A-48 추가)
- ⭐ = 업무에 영향이 커서 **우선 확인을 권장**하는 항목
- 모든 항목의 현재 상태는 `임시`입니다. 확인을 마친 항목은 제목의 `임시`를 `확정`으로 직접 바꿔 주세요.

## 1. 조직 · 입력 항목

### A-01 ⭐ 부서 목록 (초기 데이터) — 임시
영업, 생산, 구매/자재, 경영지원 (4개). 관리자가 화면에서 추가·수정·삭제할 수 있다.

영향 문서: 02, 04, 05, 06

### A-03 입력값 유형 — 임시
모든 입력값은 **숫자**(소수 허용, 최대 소수 4자리)다. 텍스트 입력 항목은 없다. 금액 단위는 **원**으로 통일한다.
영향 문서: 02, 04, 06

### A-04 ⭐ 항목 범위(scope)와 프로젝트 식별 — 임시
- 항목 범위는 두 가지다: **월 합계형**(부서·월당 값 1개) / **프로젝트별형**(프로젝트명 + 값을 여러 줄 입력).
- 프로젝트는 별도 마스터 테이블 없이 **프로젝트명 문자열**로 식별한다. 앞뒤 공백은 제거하고, 대소문자·띄어쓰기는 그대로 비교한다. 부서 간(영업 매출 ↔ 생산 원가) 같은 프로젝트명이면 같은 프로젝트로 합친다.
- 특정 프로젝트에 배분되지 않는 비용·매출은 프로젝트명 `공통`으로 입력하는 것을 관례로 한다(시스템이 특별 취급하지 않음).
- 이미 입력값이 있는 항목은 **범위(월 합계형↔프로젝트별형) 변경을 막는다**(서버 400). 기존 데이터 해석이 깨지는 것을 막기 위한 임시 규칙이다.
영향 문서: 02, 03, 04, 05, 06

### A-05 필수 여부와 0 입력 — 임시
초기 항목은 **모두 필수**다. `0`은 유효한 입력값이며 “입력 완료”로 센다(빈 칸만 미입력). 프로젝트별형 항목은 **1줄 이상** 입력해야 입력 완료로 센다.
영향 문서: 01, 02, 04

### A-06 삭제 방식(부서·입력 항목) — 임시
부서와 입력 항목의 “삭제”는 **논리 삭제**(`is_active=false`)다. 과거 제출 데이터는 보존된다. 활성 상태에서만 이름 중복을 막는다.
소속 활성 사용자가 있는 부서는 삭제할 수 없다(먼저 재배정).
영향 문서: 02, 03, 04

### A-07 ⭐ 지표 연동 키(metric_key) — 임시
- 지표 계산에 쓰이는 입력 항목은 고정된 **연동 키 16개**(`REVENUE`, `MATERIAL_COST`, `LABOR_COST`, `EXPENSE_COST`, `SGA_EXPENSE`, `PURCHASE_AMOUNT`, `COLLECTION_AMOUNT`, `RECEIVABLE_BALANCE`, `CASH_BALANCE`, `PRODUCTION_QTY`, `PRODUCTION_CAPACITY`, `HEADCOUNT`, `ORDER_RECEIVED`, `ORDER_BACKLOG`, `PIPELINE_AMOUNT`, `PIPELINE_WIN_RATE`) 중 하나를 가질 수 있다(선택).
- 관리자는 항목 생성·수정 시 연동 키를 드롭다운으로 지정할 수 있다. 연동 키가 없는 항목은 수집·조회·다운로드만 되고 지표 계산에는 쓰이지 않는다.
- 같은 월에 같은 연동 키를 가진 값이 여러 개(여러 부서/항목/프로젝트)이면 지표 계산 시 **합산**한다. 단 `PIPELINE_WIN_RATE`는 **평균**한다.
영향 문서: 02, 03, 05

### A-08 입력 안내 문구 구조 — 임시
“입력 방법 안내 문구”는 두 곳에 둔다: 부서 단위 `input_guide`(폼 상단 안내) + 항목 단위 `help_text`(각 입력 칸 아래 안내). 둘 다 관리자가 수정한다.
영향 문서: 02, 04

## 2. 사용자 · 인증

### A-09 ⭐ User 모델 구조 — 임시
“user, admin은 AbstractUser 상속” 요구를 **`User(AbstractUser)` 단일 모델 + `role` 필드(`EMPLOYEE`/`ADMIN`)**로 해석한다. (user/admin 별도 모델·다중 테이블 상속은 사용하지 않는다.)
추가 필드: `name`(성명), `role`, `department`(FK, 관리자는 비어 있을 수 있음). `first_name`/`last_name`/`email` 등 AbstractUser 기본 필드는 사용하지 않는다.
영향 문서: 02, 03

### A-10 로그인 방식 — 임시
사번을 `username` 필드에 저장한다(중복 불가). 로그인은 **성명 + 사번 + 비밀번호 세 값이 모두 일치**해야 성공한다. 실패 시 어느 값이 틀렸는지 알려주지 않는 동일한 메시지를 반환한다.
영향 문서: 02, 03, 04

### A-11 1인 1부서, 부서 공동 편집 — 임시
사용자는 **한 부서에만** 소속된다. 같은 부서 직원은 그 부서의 같은 월 보고서 1건을 **함께** 편집한다(동시 편집 충돌 방지는 하지 않으며 마지막 저장이 반영됨).
영향 문서: 01, 02, 03

### A-12 인증 토큰 방식 — 임시
DRF 기본 제공 **TokenAuthentication**(`Authorization: Token <key>`)을 사용한다. 토큰은 브라우저 `localStorage`에 저장하고, 로그아웃 시 서버에서 삭제·클라이언트에서 제거한다. 토큰 만료 시간은 두지 않는다.
영향 문서: 03, CLAUDE.md

### A-13 ⭐ 기본 관리자 생성 조건 — 임시
- “기본 관리자 계정이 없을 경우”를 **`role=ADMIN`인 사용자가 1명도 없을 때**로 해석한다. 이 경우 성명 `ADMIN` / 사번 `ADMIN` / 비밀번호 `admin1234!` 계정을 만든다.
- 생성 시점은 **Django 앱 시작 시**(`AppConfig.ready()`에서 호출, DB 미준비·마이그레이션 실행 중에는 건너뜀)이며 여러 번 실행해도 중복 생성되지 않는다(멱등).
- 초기 비밀번호는 PoC용이므로 로그인 후 관리자 화면에서 변경할 것을 화면·README에 안내한다.
영향 문서: 01, 02, 07

### A-14 비밀번호 규칙과 변경 — 임시
비밀번호는 최소 **8자**만 서버에서 검증한다(Django `AUTH_PASSWORD_VALIDATORS`는 적용하지 않음). 비밀번호 변경은 **관리자가 사용자 수정 화면에서 재설정**하는 방식만 제공한다(본인 변경·분실 찾기 기능 없음).
영향 문서: 01, 03, 04

### A-15 사용자 삭제 제한 — 임시
관리자는 **자기 자신**과 **마지막 남은 관리자**를 삭제할 수 없다. 사용자 삭제는 실제 삭제(hard delete)이며, 그 사용자가 제출한 보고서의 `submitted_by`는 비워진다(보고서는 유지).
영향 문서: 02, 03

### A-16 접근 권한 — 임시
- 직원(`EMPLOYEE`): **본인 소속 부서**의 월 실적 입력 화면만 사용한다. 대시보드·리포트·목표·사용자/부서 관리는 접근 불가.
- 관리자(`ADMIN`): 대시보드·리포트·입력 현황·목표·사용자/부서/항목 관리 전부. 관리자는 월 실적 입력 화면을 사용하지 않는다.
영향 문서: 01, 03, 04

## 3. 월 실적 입력 워크플로

### A-17 입력 대상 월 · 회계연도 — 임시
회계연도는 **1월~12월(달력 연도)**이다. 직원은 **현재 월 이하**의 월을 선택해 입력할 수 있다(미래 월 불가), 기본 선택은 현재 월이다. 시간대는 Asia/Seoul.
영향 문서: 01, 03, 04, 05

### A-18 ⭐ 상태 · 제출 후 잠금 · 중복 제출 방지 — 임시
- 보고서 상태: `DRAFT`(임시 저장) → `SUBMITTED`(제출). 화면 표시는 `미작성`(레코드 없음)/`작성 중`/`제출 완료`.
- **같은 부서·같은 월 보고서는 1건만** 존재한다(DB 유니크 제약). 이미 제출된 부서·월에 다시 제출하면 서버가 **409**로 거부한다.
- 제출 후에는 직원의 수정·업로드가 **잠긴다**.
영향 문서: 01, 02, 03, 04

### A-19 ⭐ 제출 후 정정 수단(“초안으로 되돌리기”) — 임시
제출 후 오류 정정 수단이 필요하다고 판단하여, 관리자가 입력 현황 상세에서 **제출된 보고서를 `DRAFT`로 되돌리는 기능**을 임시로 넣었다. 필요 없거나 다른 방식을 원하면 이 항목과 참조 문서에서 제거한다.
영향 문서: 01, 03, 04, 07

### A-20 제출 조건 · 진행률 정의 — 임시
- 제출은 **필수 항목이 모두 입력 완료**일 때만 가능하다(진행률 100%). 미충족 시 미입력 항목 목록과 함께 400.
- 진행률(%) = 입력 완료된 필수 항목 수 ÷ 전체 필수 항목 수 × 100 (소수점 버림). 입력 완료 기준은 A-05.
- 관리자용 요약 진행률 = 제출 완료 부서 수 ÷ 전체 활성 부서 수.
영향 문서: 01, 03, 04

### A-21 저장 방식(전체 교체) — 임시
임시 저장은 화면의 **현재 입력값 전체를 서버에 보내 해당 보고서의 값을 통째로 교체**하는 방식이다. 빈 값은 저장하지 않는다(삭제로 취급).
영향 문서: 03

### A-22 관리자의 입력값 직접 수정 — 임시
관리자는 직원이 입력한 값을 **조회만** 하고 직접 수정하지 않는다(정정은 A-19의 “되돌리기” 후 직원이 수정).
영향 문서: 01, 03, 04

### A-46 소속 부서가 없는 직원의 월 실적 API — 임시
소속 부서가 없거나 소속 부서가 삭제(비활성)된 직원이 `/my-report/…`를 호출하면 **403 `forbidden`**(“소속 부서가 없습니다. 관리자에게 문의하세요.”)으로 응답한다. 관리자 계정도 이 API는 403이다 [A-16].
영향 문서: 03, 04

### A-47 필수 항목이 0개일 때 — 임시
부서에 **활성 필수 항목이 하나도 없으면** 진행률은 **100%**(0/0)이고, 값이 없어도 제출할 수 있다(제출 시 레코드가 생성됨).
영향 문서: 03, 04

## 4. 엑셀/CSV 업로드

### A-23 파일 형식 · 제한 — 임시
`.xlsx`와 `.csv`(UTF-8 또는 UTF-8 BOM)만 지원한다(`.xls` 미지원). 파일 크기 최대 **5MB**, 데이터 행 최대 **1,000행**. `.xlsx`는 **첫 번째 시트만** 읽는다.
영향 문서: 03, 06

### A-24 ⭐ 업로드 열 구조와 반영 규칙 — 임시
- 첫 행은 헤더이며 열은 `항목명`, `프로젝트명`, `값` 세 개다(순서 무관, 헤더 이름으로 인식). 월 합계형 항목은 `프로젝트명`을 비운다.
- 대상 부서·월은 파일이 아니라 **화면에서 선택한 본인 부서·월**이다.
- 항목은 **항목명**(그 부서의 활성 항목)으로 매칭한다.
- 반영은 **전체 성공/전체 실패**(오류가 1건이라도 있으면 아무것도 반영하지 않고 행별 오류 목록 반환).
- 파일에 있는 (항목, 프로젝트명) 조합은 **기존 입력값을 덮어쓰고**, 파일에 없는 값은 **그대로 둔다**. 업로드 결과는 `DRAFT` 상태로 저장되며, 제출은 직원이 따로 한다.
- 빈 양식(템플릿) 다운로드 기능은 만들지 않는다(화면에 열 구조 안내 문구만 표시).
영향 문서: 01, 03, 04, 06

### A-48 업로드 세부 규칙 — 임시
06에 정해지지 않은 부분을 아래처럼 정했다.
- **파일 자체 오류**(파일 없음, 확장자, 5MB 초과, 데이터 1,000행 초과, UTF-8 아님, 엑셀 파일 손상, 데이터 행 없음)는 400 `upload_invalid`, `detail`에 사유, `errors.rows`는 빈 배열.
- **행 오류**는 `errors.rows = [{row, message}]`이며 `message`에는 06 §4 예시처럼 `N행:` 접두어를 포함한다(헤더 오류는 `row: 1`, 접두어 없음). 한 행에 오류가 여러 개면 모두 보고한다.
- **빈 행**: `항목명`·`프로젝트명`·`값` 세 열이 모두 비어 있는 행은 무시한다(다른 열의 내용은 보지 않음). 1,000행 제한도 빈 행을 뺀 데이터 행 기준이다.
- 항목명·프로젝트명은 앞뒤 공백을 제거하고 비교한다. 헤더에 없는 추가 열은 무시한다.
- **데이터 행이 하나도 없는 파일**(헤더만 있는 파일 포함)은 오류로 거부한다.
- 5MB = 5 × 1024 × 1024 바이트.
- 검증 순서: 권한 → 연·월(400) → 제출 잠금(409 `report_locked`) → 파일 검증(400) → 반영.
영향 문서: 03, 06

## 5. 지표 계산 (규칙 기반)

> 상세 공식은 `05-metrics.md`. 아래는 사용자가 확인해야 할 **가정의 요지**다. 공식을 바꾸려면 이 항목과 05를 함께 수정한다.

### A-25 ⭐ 집계 대상과 기간 — 임시
- 집계에는 **제출 완료(`SUBMITTED`)** 보고서만 포함한다. 임시 저장은 제외.
- **누적** = 해당 연도 1월 ~ 기준 월. **월별 리포트** = 기준 월 단독(누적값 병기).
- 기준 월에 미제출 부서가 있으면 화면에 “일부 부서 미제출” 경고를 표시하고, 제출된 데이터만으로 계산한다.
영향 문서: 03, 04, 05

### A-26 집계 유형 — 임시
연동 키마다 집계 유형이 정해진다.
- **flow(기간 합계)**: 매출·비용·매입·수금·수주·생산량·생산능력 등 → 기간 내 월별 값을 합산
- **stock(월말 잔액)**: 미수금 잔액, 현금 잔액, 수주 잔고, 파이프라인 금액, 인원수 → 기준 월 값(없으면 기준 월 이전의 가장 최근 제출 월 값, 화면에 “n월 기준” 표시)
- **rate(비율)**: 파이프라인 예상 수주 확률 → stock처럼 기준 월 값, 같은 월 복수 값은 평균
영향 문서: 05

### A-27 ⭐ 원가 · 이익 · 이익률 정의 — 임시
- 매출액 = `REVENUE` 합계
- 총원가(매출원가) = 재료비 + 노무비 + 경비 (`MATERIAL_COST` + `LABOR_COST` + `EXPENSE_COST`)
- 매출총이익 = 매출액 − 총원가
- 영업이익 = 매출총이익 − 판매관리비(`SGA_EXPENSE`)
- **이익률 = 영업이익률 = 영업이익 ÷ 매출액 × 100**, 매출총이익률도 함께 표시
- 재료비는 “매입액”이 아니라 생산 부서가 입력한 프로젝트별 재료비 합계다(재고 변동은 별도 반영하지 않음).
영향 문서: 05

### A-28 프로젝트별 분석 규칙 — 임시
프로젝트별 매출·재료비·노무비·경비를 **프로젝트명**으로 합쳐 프로젝트별 총원가·매출총이익·**매출총이익률**을 계산한다. 판매관리비는 프로젝트에 배부하지 않는다. 프로젝트별 매출이 0이면 이익률은 “-”.
영향 문서: 05

### A-29 ⭐ 공장 가동률 — 임시
**가동률(%) = 생산량 ÷ 생산 능력 × 100** (수량 기준). 누적 가동률은 월별 가동률의 평균이 아니라 **누적 생산량 ÷ 누적 생산 능력**이다.
영향 문서: 05

### A-30 ⭐ 손익분기점(BEP) — 임시
- 변동비 = 재료비, 고정비 = 노무비 + 경비 + 판매관리비
- 공헌이익률 = (매출액 − 변동비) ÷ 매출액
- **BEP 매출액 = 고정비 ÷ 공헌이익률**
- **BEP 달성률(%) = 매출액 ÷ BEP 매출액 × 100** (100% 이상이면 손익분기 초과)
- 매출액이 0이거나 공헌이익률이 0 이하이면 “산출 불가”.
영향 문서: 05

### A-31 ⭐ 3~6개월 자금 수지 예측 — 임시
- 예측 기간은 관리자가 **3~6개월** 중 선택(기본 3개월).
- 기준 잔액 = 기준 월 `CASH_BALANCE`(stock 규칙).
- 월 예상 유입 = 최근 3개월(기준 월 포함, 제출 데이터가 있는 달만) **평균 수금액**(`COLLECTION_AMOUNT`)
- 월 예상 유출 = 같은 기간 **평균(매입액 + 노무비 + 경비 + 판매관리비)** (재료비는 매입액과 이중 계산되지 않도록 제외)
- 예상 순현금흐름 = 예상 유입 − 예상 유출, 예상 기말 잔액(t) = 예상 기말 잔액(t−1) + 순현금흐름. 유입·유출은 예측 기간 내내 동일하다고 가정한다.
- 예상 잔액이 0 미만인 달은 “자금 부족 예상”으로 표시한다.
- 제출된 데이터가 있는 달이 없으면 “산출 불가”.
영향 문서: 05

### A-32 ⭐ 인당 생산성 — 임시
전사 인원 = 4개 부서(연동 키 `HEADCOUNT`)의 월말 인원수 합계.
**인당 매출액 = 매출액 ÷ 전사 인원**, **인당 영업이익 = 영업이익 ÷ 전사 인원**, **인당 생산량 = 생산량 ÷ 전사 인원**. 누적은 기간 합계 ÷ 기준 월 전사 인원(월말 인원 기준).
영향 문서: 05

### A-33 매입 · 매출 · 미수금 현황 — 임시
표시 지표: 매출액, 매입액, 당월 수금액, 미수금 잔액, **미수금 비율 = 미수금 잔액 ÷ 해당 기간 매출액 × 100**.
영향 문서: 05

### A-34 수주 잔고 · 영업 파이프라인 — 임시
표시 지표: 신규 수주액(기간 합계), 수주 잔고(월말), 파이프라인 금액(월말), 예상 수주 확률, **가중 파이프라인 = 파이프라인 금액 × 예상 수주 확률 ÷ 100**.
영향 문서: 05

### A-35 ⭐ 연간 목표 지표와 달성률 — 임시
- 목표 설정 대상 지표(5개): **매출액**(연간 누적), **영업이익률**(%), **가동률**(%), **생산량**(연간 누적), **신규 수주액**(연간 누적). 연도별로 저장한다.
- **달성률(%) = 실적 ÷ 목표 × 100** (모두 높을수록 좋은 지표로 가정). 이익률·가동률의 실적은 누적 기준 값. 100%를 넘어도 제한하지 않는다. 목표가 없으면 “목표 미설정”.
영향 문서: 02, 03, 04, 05

### A-36 표시 형식과 계산 불가 처리 — 임시
금액은 원 단위에 천 단위 콤마, 비율은 소수 1자리(%), 수량은 정수 콤마. 0으로 나누기 등으로 계산할 수 없는 값은 **“-”**로 표시하고(API에서는 `null`) 오류로 처리하지 않는다.
영향 문서: 04, 05

## 6. 기술 · 환경

### A-37 ⭐ 버전과 필수 패키지 — 임시
- Python 3.12 이상, **Django 5.2 LTS**, Django REST Framework 최신 안정판, **psycopg 3**(`psycopg[binary]`, PostgreSQL 드라이버), **openpyxl**
- Node.js LTS, **Vue 3 최신 안정판**, **Vite 최신 안정판**, **Bootstrap 5.0.x**(요구 사항의 “5.0” 준수), **Chart.js 4.x**
영향 문서: CLAUDE.md, README.md

### A-38 프런트엔드 보조 도구 — 임시
SPA 화면 전환을 위해 **Vue Router**를 사용한다. 상태관리 라이브러리(Pinia 등), HTTP 라이브러리(axios 등), Chart.js 래퍼(vue-chartjs 등)는 **도입하지 않는다**(브라우저 `fetch`, Vue 기본 반응형 상태, Chart.js 직접 사용). Bootstrap의 **JavaScript는 사용하지 않고 CSS만** 사용한다(모달·드롭다운은 Vue로 구현).
영향 문서: CLAUDE.md, 04

### A-39 개발 서버와 프록시 — 임시
Django `runserver` 8000번, Vite dev 서버 5173번. 개발 중 CORS 설정 대신 **Vite 프록시**(`/api` → `http://127.0.0.1:8000`)를 사용한다(`django-cors-headers` 미사용). 배포는 범위 밖.
영향 문서: CLAUDE.md, 07

### A-40 DB 접속 설정 — 임시
DB 이름 `management_dashboard`, 호스트 `localhost`, 포트 `5432`. 사용자·비밀번호는 **환경변수**(`DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`)로 받고, 기본값은 Postgres.app 기본 설정에 맞춰 “로컬 OS 사용자, 비밀번호 없음”으로 한다. `.env` 파일 로딩 라이브러리는 쓰지 않는다.
영향 문서: CLAUDE.md, README.md

### A-41 폴더 구조와 Django 앱 구성 — 임시
루트에 `backend/`, `frontend/`, `specs/`를 둔다. Django 프로젝트 패키지명 `config`, 앱은 `accounts`(사용자·인증), `organization`(부서·입력 항목), `reports`(월 실적·업로드), `goals`(연간 목표), `analytics`(지표 계산·대시보드·리포트·다운로드). 자세한 트리는 CLAUDE.md.
영향 문서: CLAUDE.md

### A-42 테스트 방식 — 임시
백엔드는 Django 기본 테스트 러너(`python manage.py test`)로 **지표 계산식·제출/중복 방지·업로드 검증·권한**을 중심으로 테스트한다. 프런트엔드 자동화 테스트 도구는 도입하지 않고 `npm run build` 성공과 수동 확인으로 검증한다.
영향 문서: CLAUDE.md, 07

### A-43 다운로드 형식 — 임시
“엑셀(CSV) 다운로드”를 **CSV**로 해석한다(UTF-8 BOM, 엑셀에서 한글이 깨지지 않도록). 구조는 세로형 한 파일: `섹션, 항목, 구분, 단위, 값` (구분 = 프로젝트명 또는 월). `.xlsx` 다운로드는 만들지 않는다.
영향 문서: 03, 05

### A-44 UI 언어 · 로케일 · 화면 대상 — 임시
UI 문구는 **한국어**, Django `LANGUAGE_CODE=ko-kr`, `TIME_ZONE=Asia/Seoul`. 화면은 **데스크톱 브라우저 우선**(모바일 최적화는 목표 아님, Bootstrap 기본 반응형 수준).
영향 문서: 04, CLAUDE.md

### A-45 API 규약 — 임시
경로 접두어 `/api/`, JSON, **페이지네이션 없음**(PoC 데이터 규모 가정), 오류 응답 형식 `{"code", "detail", "errors"}`. 자세한 내용은 `03-api.md`.
영향 문서: 03
